# What a decision record can give a reader who never held the theory

Peter Naur (1985) argued that a program's real substance is a theory held by the people who built it. Having that theory means being able to say how the code maps onto the world, why each part is the way it is, and how a novel change relates to what already exists. Reestablishing a program "merely from the documentation," Naur wrote, "is strictly impossible." For Naur, that was an end-of-life event, when a team dispersed. Agentic coding makes it the ordinary condition of work. Every session starts with an agent that never held the theory and has only what is written down. So the useful question for the field is not whether documentation transfers theory, since Naur is largely right that it doesn't, but what a written record can still give a reader who never had it.

My claim is that a decision record gives an agent enough to falsify the reasoning behind a decision, but not enough to start that challenge or to foresee consequences nobody has written down. Practices that treat an architecture decision record (ADR) folder as the agent's stand-in for understanding the project overestimate the first capability and ignore the two limits.

Michael Nygard's (2011) case for ADRs is about rationale, not theory. A newcomer who lacks a decision's rationale, he argues, can only accept it blindly or reverse it blindly; a record lets them do neither. Nygard asks for each ADR to be written as a conversation with a future developer, and assumes that developer can judge the rationale. Naur denies that a newcomer has the theory to judge it with. An agent is the most literal version of Nygard's future developer, which makes it a clean test between the two.

My own project offers one such test. An ADR (0004) justified dropping a challenged player straight into a live mini-game, on the grounds that this matched the app's trust-based logging model: "a mini-game challenge is no different." The message that later reversed it was pure UX frustration, a hurried request for an accept-the-invite popup before a match starts. The request mentions neither 0004 nor trust nor logging. Yet the agent that wrote 0007, a week later, read 0004's recorded reasoning and named the flaw precisely: trust-based logging concerns whether a past claim is believable; it "was never an argument for dropping someone into an active match with no say in the matter." The project's research log, written at the time, records that 0007 worked from 0004's text (research-log/index0.md, 2026-10-28). The analysis, that 0004 had conflated believability with consent, came from the written record, not from any memory of writing it. That is far less than Naur's theory, one sentence rather than the system, but "strictly impossible" leaves no room even for that.

Two limits pull the other way. First, the agent did not start the challenge. That request did, and I was the one person holding the theory from 0004 to 0007. Storey's (2026) triple debt model separates two things Naur runs together: cognitive debt (lost understanding in people) and intent debt (rationale never externalized for humans or agents to read). 0004 carried no intent debt: its rationale was written down, which is what let the agent articulate the flaw. But noticing that something was wrong was a cognitive-layer job, and it stayed with me. Böckeler (2026) finds the same boundary in tooling: neither deterministic checks nor LLM-based review reliably catch misunderstood instructions, and her stated goal for a harness is to direct human input where it matters most, not to eliminate it.

Second, and most seriously, 0007's own fix was a full-page reload, chosen to avoid building per-viewer broadcast plumbing. It created a race between a user's own broadcast and their pending navigation, which a later ADR (0009) had to repair. A Naur loyalist would say this proves his point: the record carried forward argument, not understanding, and only understanding predicts behaviour. I concede this for runtime consequences, but it locates the limit rather than extending it to everything. Nygard asks that every consequence be listed, not just the positive ones, and this course asks authors to give consequences "the most care" (Swift, 2026). 0007's consequences section did not contain the race because nobody had thought of it yet. A record can expose reasoning that someone wrote down, not a consequence that existed in nobody's head. That is not documentation failing to transfer a theory; there was no theory to transfer.

The scope of this evidence is narrow. Two reversals in one student project show that this mechanism exists, not how often it operates in the field. They show that "strictly impossible" is too strong a claim about design rationale, and that an ADR's value in agentic work depends on a human who still holds the theory.
